💡 ทำไม Context ใน Workshop จึงยาวขึ้น? เพราะผู้บริหารไม่ควรทดลอง AI จากโจทย์สั้น ๆ ที่ไม่มีรายละเอียดจริง — Context ที่ดีควรมี Fact, Stakeholder, Timeline, Constraint, สิ่งที่รู้/ยังไม่รู้ และจุดที่ต้องใช้ Human Judgment เพื่อให้เห็นว่า AI ช่วย “จัดการความซับซ้อน” ได้อย่างไร

PAGE 2 · CASE-BASED MEDICAL COMMUNICATION

Medical Communication Lab — แต่ละสถานการณ์มี Context ของตัวเอง

แต่ละกิจกรรมด้านล่างเป็นสถานการณ์จำลองที่แยกจากกัน และมี Context / Source / ข้อจำกัด ของตัวเอง ผู้เรียนจึงสามารถเลือกทดลองเป็นรายกรณีได้ทันที โดยไม่ต้องอ้างอิง Context กลางจากด้านบน

📎 Trusted Source First: ให้ AI เริ่มจากข้อมูลที่องค์กรยืนยันแล้ว ไม่ใช่เริ่มจากสิ่งที่ AI จำมาเอง หาก Context ไม่ได้ให้ข้อมูลบางเรื่อง ต้องระบุว่า “ข้อมูลไม่เพียงพอ / Source ไม่ได้กำหนด” แทนการเติมข้อเท็จจริงเอง

PAGE 3 · AI PROTOTYPE PLAYGROUND

จาก “AI ตอบข้อความ” → สู่ “AI สร้างของที่เล่นได้”

ส่วนนี้ไม่สอนเขียนเกมและไม่มี Prompt เพิ่มเติม จุดประสงค์คือให้ผู้เรียนเล่นจริง แล้วเห็นว่า Generative AI สามารถช่วยสร้าง Interactive Prototype ที่มี UI, Logic, Score, Mobile Control, Sound และ Interaction ได้

สังเกตระหว่างเล่น: สิ่งนี้ไม่ได้เป็น “ข้อความตอบกลับ” แต่เป็น software prototype ที่มี state, rules และ interaction — และยังต้อง Human Test ก่อนใช้จริงเสมอ
